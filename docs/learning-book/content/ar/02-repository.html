2. المستودع — أين يوجد كل شيء

DokTool مستودع Git واحد (monorepo) يضم ثلاثة تطبيقات وأربع حزم مشتركة. لوحة الويب وتطبيق الهاتف منفصلان تمامًا من الأصل: يعيشان في مجلدين مختلفين، بلغتين وإطارين مختلفين، ولا يستورد أحدهما شيفرة الآخر أبدًا. ما يتشاركانه هو عقد مع الخادم، يُولَّد آليًا.

2.1 المجلدات العليا

doktool/ ├── apps/ │ ├── api/ ← the server (NestJS, TypeScript). The ONLY part that touches the database. │ │ ├── src/ code: main.ts, app.module.ts, common/, config/, infrastructure/, modules/, scripts/ │ │ ├── prisma/ schema.prisma (47 tables) + migrations/ (hand-written SQL) │ │ └── test/ unit/ (pure logic) and integration/ (real HTTP + real PostgreSQL) │ ├── admin/ ← Admin Web (Next.js, React, TypeScript). The team's browser console. │ │ ├── src/app/ the pages (one folder = one URL) │ │ ├── src/features/ the screens, one folder per console section │ │ ├── src/ui/ the shared components (Button, DataTable, Dialog, Drawer…) │ │ └── src/api/ the typed API client (schema.d.ts is generated) │ └── mobile/ ← the app (Flutter, Dart) for iOS and Android. │ ├── lib/src/core/ networking, session, local database, secure storage │ ├── lib/src/features/ one folder per feature (onboarding, library, calculators…) │ ├── lib/src/ui/ the shared widgets (DtButton, DtAlert, ContentRow…) │ └── test/ widget and unit tests ├── packages/ │ ├── api-contract/ openapi.json — the contract both clients are generated from │ ├── design-tokens/ colours, spacing, radii… → CSS, Tailwind, TypeScript and Dart │ ├── i18n/ messages.fr.json + messages.en.json → Flutter ARB + admin catalogue │ └── calculator-vectors/ test cases both calculator engines must pass ├── design/ the design system: specifications, component cards, tokens.json └── docs/ decisions (adr/), audits, operations guides, this book

باختصار: apps/api هو الخادم ووحده يلمس قاعدة البيانات؛ apps/admin لوحة الإدارة في المتصفح؛ apps/mobile تطبيق الهاتف لـiOS وAndroid؛ وpackages/ ما يتشاركونه: العقد، الرموز التصميمية، النصوص، وحالات اختبار الحاسبات.

2.2 كيف ينفصل تطبيق الويب عن تطبيق الهاتف

سؤال « أين شيفرة الويب، وأين شيفرة الهاتف؟ » له جواب واضح:

لوحة الإدارة (الويب)تطبيق الهاتف
المجلدapps/adminapps/mobile
اللغةTypeScript + React (TSX)Dart
الإطارNext.js (App Router)Flutter
من يستعملهفريق DokTool، على حاسوب (≥ 1024 بكسل)الأطباء والمقيمون والطلبة وزوار العرض التجريبي، على الهاتف
الـAPI الذي يستدعيه/admin/v1/* بكعكة جلسة + مصادقة ثنائية/v1/* برمز Bearer
العميل المولَّدapps/admin/src/api/schema.d.tsapps/mobile/lib/src/core/api/generated/
مدير الحزمnpm (مساحة عمل)flutter pub
الاختباراتVitest (apps/admin/src/test)flutter test (apps/mobile/test)

الأشياء الوحيدة المشتركة بينهما تأتي من packages/: الكلمات نفسها (i18n)، الألوان نفسها (الرموز التصميمية) وعقد الـAPI نفسه. لا شيء منها يُستورَد كشيفرة مصدرية؛ كلٌّ منها يُولَّد بالصيغة التي يحتاجها التطبيق.

design/system/tokens.json ──generate──► tokens.css + tailwind preset (admin) + doktool_tokens.dart (mobile) packages/i18n/messages.*.json ─build──► admin catalogue (TS) + lib/l10n/*.arb (mobile) apps/api (decorators) ──openapi──► packages/api-contract/openapi.json ──► schema.d.ts (admin) + Dart client (mobile)
لا تعدّل ملفًا مولَّدًا باليد أبدًا. schema.d.ts، وكل ما تحت core/api/generated/، وdoktool_tokens.dart وملفات ARB تُعاد كتابتها بمولّداتها. يقارنها CI بتوليد جديد ويفشل عند أي اختلاف ("drift").

2.3 كيف تتحادث التطبيقات الثلاثة

┌────────────────────┐ HTTPS /v1/* (Bearer access token) ┌──────────────────────────┐ │ Mobile (Flutter) │ ─────────────────────────────────────────────► │ │──► PostgreSQL (Prisma) └────────────────────┘ │ API (NestJS) │──► Cloudflare R2 (files) ┌────────────────────┐ HTTPS /admin/v1/* (cookie + TOTP 2FA) │ apps/api — the judge │──► SMS / e-mail providers │ Admin Web (Next.js)│ ─────────────────────────────────────────────► │ of every rule │──► Chargily / SATIM payments └────────────────────┘ └──────────────────────────┘ PDFs and photos go straight between the apps and R2 with short-lived signed URLs the API hands out.

الهاتف ولوحة الإدارة يتحدثان مع الخادم فقط. الخادم هو الحَكَم في كل قاعدة، ويتحدث مع قاعدة البيانات وتخزين الملفات R2 ومزوّدي الرسائل وبوابات الدفع. ملفات PDF والصور تنتقل مباشرة بين التطبيقات وR2 عبر روابط موقّعة قصيرة العمر يمنحها الخادم.

2.4 داخل apps/api

  • src/main.ts — يشغّل الخادم. src/app.setup.ts — إعدادات HTTP المشتركة مع الاختبارات. src/app.module.ts — يجمع كل شيء.
  • src/config/ — يقرأ متغيرات البيئة ويتحقق منها (env.ts).
  • src/common/ — أدوات صغيرة مشتركة: غلاف الأخطاء، معلومات المتصل، CSV ونص البحث.
  • src/infrastructure/ — خدمات تقنية تستعملها كل وحدة: عميل قاعدة البيانات، التشفير، المهام الخلفية، حدود المعدّل، البريد والرسائل القصيرة، التحقق من الرموز.
  • src/modules/ — الوحدات العشرون للمجال، واحدة لكل مجال عمل. كل وحدة تملك جداولها ولا تكشف إلا ما يصدّره ملف index.ts الخاص بها.
  • src/scripts/ — أدوات سطر الأوامر: إنشاء مشرف، توليد عقد OpenAPI، تعبئة بيانات العرض، استخراج Medicalcul واستيراده.
  • prisma/schema.prisma — كل الجداول، مجمّعة حسب الوحدة المالكة.

2.6 تشغيل كل شيء على جهازك

من جذر المستودع، مرة واحدة:

npm install # installs API, Admin Web and packages cp apps/api/.env.example apps/api/.env # then fill DATABASE_URL and fresh 32+ char secrets cp apps/admin/.env.example apps/admin/.env npm run prisma:migrate:deploy -w @doktool/api # creates the tables npm run admin:create -w @doktool/api -- --email you@example.dz --name "Your Name"

ثم في ثلاث نوافذ طرفية:

npm run start:dev -w @doktool/api # API on http://localhost:3000 (Swagger at /docs) npm run dev -w @doktool/admin # Admin Web on http://localhost:3001 cd apps/mobile flutter pub get dart run build_runner build --delete-conflicting-outputs flutter gen-l10n flutter run --dart-define=API_BASE_URL=http://localhost:3000
بيانات تجريبية. الأمر npm run demo:seed -w @doktool/api يملأ قاعدة بيانات ينتهي اسمها بـ_demo بحسابات ومحتوى للعرض (ويرفض أي قاعدة أخرى). كلمات المرور التي يطبعها تُعرض مرة واحدة فقط.

2.7 الأمر الوحيد الذي يفحص كل شيء

DATABASE_URL=postgresql://…/doktool_test npm run ci cd apps/mobile && flutter analyze && flutter test

يشغّل npm run ci بالترتيب: تنسيق Prettier، فحص ESLint، فحص أنواع TypeScript، فحص تماثل الترجمة (كل مفتاح باللغتين)، فحص الرموز التصميمية (لا لون ولا نصف قطر ولا ضبابية ولا مدة مكتوبة مباشرة في الشيفرة)، فحص انحراف OpenAPI، فحص انحراف عميل لوحة الإدارة، ثم كل اختبارات كل مساحة عمل. في نهاية تدقيق أكتوبر 2026 كان كله أخضر: 613 اختبارًا للخادم، 30 اختبارًا للوحة الإدارة، اختبارات الحزم، و167 اختبار Flutter.
