14. العمل على الشيفرة: الاختبارات، CI، والوصفات

أنت تعرف الآن أين يوجد كل شيء. هذا الفصل الأخير عملي: كيف تفحص عملك، والخطوات الدقيقة للتغييرات التي ستقوم بها كثيرًا.

14.1 قبل كل commit

DATABASE_URL=postgresql://…/doktool_test npm run ci # format, lint, types, i18n, tokens, contract, all tests cd apps/mobile && flutter analyze && flutter test npm run build -w @doktool/admin # when Admin Web changed
استعمل قاعدة بيانات مخصّصة للاختبار. اختبارات التكامل لا تتراجع عن تغييراتها. والاختبار الذي يغيّر شيئًا على مستوى المنصة (مثل سياسة التوقيع المزدوج) يجب أن يعيده، كما يفعل clinical-review.e2e.spec.ts.

14.2 وصفة: إضافة نقطة نهاية للخادم

  1. اكتب دالة الخدمة في الوحدة التي تملك البيانات (مع تعليق من سطر واحد).
  2. أضف أصناف DTO (@ApiProperty + مزخرفات class-validator).
  3. أضف دالة المتحكم مع الحارس المناسب: UserAuthGuard، ViewerAuthGuard، @RequireFeature أو @RequireGrants. التغييرات الإدارية تستدعي AuditService.record مع السبب.
  4. اكتب اختبار تكامل في apps/api/test/integration.
  5. أعد توليد العقد والعميلين:
npm run openapi:generate -w @doktool/api npm run generate:api -w @doktool/admin cd apps/mobile && dart run swagger_parser && dart run build_runner build --delete-conflicting-outputs

14.3 وصفة: إضافة عمود أو جدول

  1. عدّل apps/api/prisma/schema.prisma في قسم الوحدة المالكة (// ── [module] ──)؛ اختبار وحدة يفحص ملكية الجداول.
  2. اكتب الترحيل (migration) باليد في prisma/migrations/<timestamp>_<name>/migration.sql. إضافة قيمة إلى enum (ADD VALUE) تكون في ترحيل خاص بها.
  3. الفهارس المكتوبة بـSQL (trigram، الجزئية) تُصرَّح أيضًا في المخطط، وإلا سيقترح prisma migrate diff حذفها. افحص بـnpx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --exit-code.
  4. npm run prisma:migrate:deploy -w @doktool/api، ثم يعمل prisma generate عند التثبيت.

14.4 وصفة: إضافة نص أو تغييره

// keys.json { "fr": { "mobile.home.newKey": "Bonjour" }, "en": { "mobile.home.newKey": "Hello" }, "remove": [] } npm run add-keys -w @doktool/i18n -- keys.json npm run build:arb -w @doktool/i18n cd apps/mobile && flutter gen-l10n

لوحة الإدارة تقرأ الكتالوج مباشرة؛ والهاتف يستعمل AppLocalizations.of(context).homeNewKey. ويفشل CI إن وُجد مفتاح بلغة واحدة فقط.

14.5 وصفة: إضافة شاشة في الهاتف

  1. أنشئ الشاشة في lib/src/features/<feature>/، مبنية من ودجات lib/src/ui والرموز التصميمية فقط.
  2. أضف مسارها إلى Routes وGoRoute في app_router.dart؛ وإن كانت للحسابات الحقيقية فقط، أضفها إلى Routes.accountOnly.
  3. حمّل البيانات عبر مزوّد؛ وارسم حالات التحميل (هيكل)، والخطأ (« Réessayer »)، والفراغ.
  4. الأشياء المقفلة تبقى ظاهرة: استعمل ملف الوصول وLockLabel وshowLockSheet.
  5. أضف اختبار ودجت، وأضف الشاشة إلى accessibility_test.dart.
  6. نسّق بـdart format --page-width 120 (ولا تنسّق doktool_tokens.dart أبدًا).

14.6 وصفة: إضافة قسم في لوحة الإدارة

  1. نقاط النهاية في الخادم مع @RequireGrants؛ الصلاحية الجديدة تُضاف في grants.ts وعنوانها في features/permissions/grants.ts (يفشل البناء حتى تُعنوَن).
  2. src/features/<section>/: الصفحة، لوحاتها ونوافذها، وlabels.ts لأسماء الحالات وألوانها.
  3. src/app/admin/<section>/page.tsx يغلّفها بـ<RequireGrant>، ورابط في shell/nav.ts.
  4. كل تغيير يطلب سببًا (ReasonDialog) ويعرض إشعارًا عند النجاح.

14.7 إضافة حاسبة ليست تغييرًا في الشيفرة

الحاسبة الجديدة بيانات، يُدخلها طبيب في لوحة الإدارة من مصدر مذكور (الفصل 13.5)، يراجعها شخص آخر، ثم تُنشر. لا حاجة لنشر نسخة جديدة من البرنامج: الهواتف تستلمها في القائمة أو المزامنة التالية. المحرّكان لا يتغيّران إلا عند الحاجة إلى نوع جديد من العمليات أو المدخلات — وعندها يتغيّر المحرّكان وcheckDefinition والمتجهات المشتركة ورقم إصدار المحرّك معًا.

14.8 قائمة الفحص التي تحفظ أمان DokTool

القاعدةأين تُفرض
كل نقطة نهاية تعيد فحص الوصول@RequireFeature، AccessService.decideItems، @RequireGrants
لا بيانات مرضى، ولا نص حر في التحليلاتمخططات analytics.policy.ts؛ قيم الحاسبات لا تُرسل أبدًا
الملفات عبر StorageService فقط، موقّعة وقصيرة العمرstorage.policy.ts، وقاعدة استيراد في ESLint
الرموز: الوصول في الذاكرة، التحديث في Keychain/Keystore، لمرة واحدة، مرتبط بالجهازsession_vault.dart، sessions.service.ts
الإدارة: كعكة + TOTP، الكتابة فقط من لوحة الإدارة، فصل المهامadmin-guards.ts، grants.ts
المحتوى السريري: موثّق المصدر، مُختبَر، المؤلف ≠ المراجِع، لا يتغيّر بعد النشرcalculators-admin.service.ts، pregnancy-admin.service.ts، قيود قاعدة البيانات
كل تغيير إداري مسجَّل، والسجل للإضافة فقطAuditService، مشغّلات الجدول (triggers)
خلايا CSV لا تُنفَّذ كصيغcommon/text/csv.ts

14.9 ما الذي غيّره تدقيق أكتوبر 2026

التقرير الكامل هو docs/CODE-AUDIT-2026-10.md. باختصار: ثمانية عشر عيبًا أُصلحت مع اختبارات (أخطرها: إعادة التحقق التي كانت تُسقط وصول طبيب مشترك، وحالة سباق في استرجاع الحساب)، تحسّن أداء بيان العمل دون اتصال والمفضلة نحو عشر مرات، تعليقات أُضيفت لكل دالة وكل زر في التطبيقات الثلاثة، وست توصيات مسجّلة لقرارات تحتاج مالك المنتج أو دلو R2 حقيقيًا.

14.10 إعادة بناء هذا الكتاب

python3 docs/learning-book/build.py # HTML + PDF, English and Arabic (needs Chrome) python3 docs/learning-book/build.py --html # HTML only

الفصول في docs/learning-book/content/en وcontent/ar؛ ومقدمات المجلدات في folders.json. مقتطفات الشيفرة والملحق أ تُقرأ من المصادر وقت البناء، فبعد أي تغيير في الشيفرة تكفي إعادة البناء لتحديث الكتاب. والعنصر النائب الذي لم يعد مرساه موجودًا يوقف البناء ويذكر اسمه، فلا يتقادم شيء بصمت.
