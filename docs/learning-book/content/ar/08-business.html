8. التحقق، الدفع، المالية، التحليلات، التدقيق، أمان الإدارة

هذه الوحدات تحوّل التسجيل إلى مهني مشترك، وتعطي الفريق أدوات تشغيل الخدمة: فحص الشهادات، قبض المدفوعات، حساب المال، قياس الاستعمال دون تجسّس، الاحتفاظ بسجل لا يُعدَّل لكل فعل إداري، وحماية لوحة الإدارة نفسها.

8.1 التحقق

يثبت الشخص أمرين، في ملفين منفصلين: هويته (بطاقة تعريف وطنية، جواز سفر، أو بطاقة طالب للطلبة) وصفته — التسجيل الجامعي للطالب (STUDENT_STATUS)، والإقامة أو التسجيل في عمادة الأطباء للمقيم أو الطبيب (PROFESSIONAL_STATUS).

PREPARING ──submit──► SUBMITTED ──claim──► IN_REVIEW ──approve──► VERIFIED ──(expiry)──► EXPIRED ▲ │ renew: a new case from 60 days before └──────── start again ◄──── reject (reason)┘ after 2 rejections: APPEALED → decided by a DIFFERENT reviewer

المراحل: تحضير ← إرسال ← أخذ الملف من مراجِع ← قبول (VERIFIED) أو رفض بسبب؛ يمكن البدء من جديد بعد الرفض، والاستئناف بعد رفضين يقرّره مراجِع آخر؛ والتجديد ممكن قبل الانتهاء بـ60 يومًا.

في جانب المراجِع (VerificationReviewService)، يأخذ المراجِع ملفًا (فلا يقرّر شخصان الملف نفسه)، ويعرض الوثائق في عارض مقيَّد (روابط موقّعة لـ60 ثانية، علامة مائية باسم المراجِع، كل عرض مسجَّل)، ثم يقبل أو يرفض بكود سبب. القبول ينسخ الصفة المُثبتة والتفاصيل إلى الملف الشخصي ويجدول حذف الوثائق: لا تُحفظ الملفات إلا بقدر ما تسمح قاعدة الاحتفاظ.

8.2 الفوترة: الخطط، الدفع، البوابات

الخطط لها إصدارات: ينشر المشرف العام إصدار خطة بسعره ومدته وأسطر « inclus / non inclus » (مشمول / غير مشمول)؛ تغيير السعر إصدار جديد، والاشتراكات الجارية تحتفظ بإصدارها. والدفع مفتوح فقط لطبيب أو مقيم نشط مُتحقَّق من صفته المهنية (الطلبة لا يدفعون أبدًا؛ ولا أحد يدفع قبل التحقق — ADR-006 Q6).

8.6 أمان الإدارة: كلمة المرور، TOTP، الصلاحيات

/sign-in email + password ─► AdminAuthService.signIn lockout after 5 failures; same timing for unknown e-mails ◄─ 5-minute challenge: ENROL (first time: QR code) or VERIFY 6-digit TOTP code ───► completeTotp ─► opaque session cookie (idle + absolute timeouts) every admin request: AdminBoundaryGuard (no bearer tokens; writes only from the Admin Web origin) AdminSessionGuard (live session + the route's @RequireGrants)

الدخول: البريد وكلمة المرور (قفل بعد 5 محاولات خاطئة، وزمن الرد نفسه لبريد غير معروف) ← تحدٍّ لـ5 دقائق: تسجيل تطبيق المصادقة بأول مرة (رمز QR) أو التحقق ← رمز TOTP من 6 أرقام ← كعكة جلسة. وكل طلب إداري يمر بحارسين: حدود الثقة (لا رموز Bearer، والكتابة فقط من مصدر لوحة الإدارة) ثم الجلسة والصلاحيات المطلوبة.

8.7 وحدة admin

modules/admin تضم شاشات قراءة تجمع عدة وحدات: « Vue d'ensemble » (شريط الأرقام وقوائم العمل)، « Utilisateurs » (البحث ولوحة المستخدم: الملف، الوصول مع مدخلاته، الاشتراكات، أعداد النشاط)، وسجل التدقيق مع تصديره CSV.
