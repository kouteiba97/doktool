13. ثماني رحلات عبر النظام كله

كل رحلة تتبع قصة حقيقية واحدة من أول ضغطة إلى قاعدة البيانات والعودة، مع ذكر الملف في كل خطوة. اقرأ واحدة والتطبيقات الثلاثة مفتوحة جنبًا إلى جنب: إنها أسرع طريقة لتشعر كيف تتلاءم القطع.

13.1 طبيب ينضم، يُتحقَّق منه، ويشترك

MOBILE API ADMIN WEB welcome_screen « Créer un compte » role_select_screen DOCTOR (in memory) sign_up_screen ─ POST /v1/auth/sign-up ─► AuthService.signUp → OtpService.issue → SMS/e-mail otp_screen ───── POST …/sign-up/confirm ► confirmSignUp → session + tokens; DemoService.markConverted └── POST /v1/me/professional-profile (DOCTOR) UsersService verification_intro → identity_step (camera, ML Kit check) POST /v1/me/verification/cases …/uploads → signed PUT → R2 doktool-private → …/documents (confirm) status_step (Ordre number, specialty, attestation) → saveDetails summary_screen « Envoyer » ─────────────► VerificationService.submit (SUBMITTED) Vérifications queue (SLA 24 h) « Prendre le dossier » (claim) restricted viewer (60 s, audited) VerificationReviewService.approve ◄─ « Approuver » profile ← role + details; notification; audit entry notification « Vérification approuvée » AccessService → tier PROFESSIONAL_UNPAID, purchase OPEN plans_screen « Choisir » → review_screen « Payer » ─► CheckoutService.start → Chargily page browser pays on the gateway's page payment_result_screen polls ─────────────► settle → gateway.status = PAID → activate subscription access reloads → tier PROFESSIONAL: every model, calculator and profile opens; offline sync starts

الملخص: التسجيل والرمز ← اختيار الصفة ← وثائق الهوية والصفة إلى الدلو الخاص ← الإرسال ← في لوحة الإدارة يأخذ مراجِع الملف ويفحص الوثائق في العارض المقيَّد ثم يقبل ← يصبح الطبيب PROFESSIONAL_UNPAID ويُفتح له الشراء ← يدفع على صفحة البوابة ← يسأل الخادم البوابة ويفعّل الاشتراك ← يصبح PROFESSIONAL ويُفتح كل شيء وتبدأ المزامنة دون اتصال.

13.2 زائر يجرّب العرض ثم ينشئ حسابًا

  1. demo_start_screen ← POST /v1/demo/sessions مع معرّف التثبيت ← رمز عرض لساعة + رمز تجديد (SessionVault.saveDemo).
  2. ينتقل الموجّه إلى الشاشة الرئيسية؛ وGET /v1/me/access يجيب بالمستوى DEMO: فقط عناصر demoSample تُفتح؛ والعمل دون اتصال والشراء وتعديل الملف مقفلة مع « Créer un compte » كمسار للفتح.
  3. التحليلات: DEMO_STARTED، ثم DEMO_FEATURE_VIEWED لكل وحدة شوهدت أو حدّ بُلغ (دون حساب، ودون بيانات شخصية).
  4. « Créer un compte » ← التسجيل ← عند التأكيد يعلّم معرّف التثبيت نفسه العرض بأنه CONVERTED؛ ومسار « Démo » في لوحة الإدارة يحتسبه.

13.3 فتح نموذج وصفة

تتبّع الفصل 3.1 هذا الطلب بايتًا بايتًا. ما يجب تذكّره: القائمة تعرض النماذج المقفلة في مكانها؛ file-url يعيد فحص الوصول؛ ملف PDF يأتي مباشرة من R2 برابط لـ10 دقائق؛ تُفحص بصمته SHA-256 على الهاتف؛ ActivityRecorder.referenceViewed يضيف إدخالًا إلى السجل؛ وREFERENCE_VIEWED يُحتسب بعد أن يُرسم الملف.

13.4 استعمال حاسبة، دون اتصال

  1. أثناء آخر مزامنة، حفظ OfflineSyncController إصدار الحاسبة المنشور (التعريف + حالات الاختبار) في drift.
  2. لا شبكة: calculatorRuntimeProvider يقرأ الإصدار المحفوظ، يقرأ تعريفه (definition.dart) ويشغّل حالات اختباره المنشورة على محرّك Dart (self_test.dart). أي فشل يعني رفض الحاسبة.
  3. يكتب الطبيب العمر والوزن والكرياتينين؛ كل حقل يُثبَّت بعد توقف؛ evaluate() يفحص النطاقات والقواعد ويحسب؛ فيظهر الشريط والصيغة مع القيم.
  4. لا شيء يغادر الهاتف. يُضاف CALCULATOR_COMPLETED إلى طابور التحليلات بمعرّف الحاسبة وإصدارها فقط.

13.5 تأليف حاسبة ونشرها (مشرفان)

Author (calculators.draft) Reviewer (calculators.review + publish), NOT the author « Nouveau calculateur » → createCalculator « Nouvelle version » → createVersion (DRAFT) Définition: JSON from the cited source → saveDefinition (checkDefinition) Sources: PRIMARY source (+ validation sources) Tests: cases from the source → « Lancer les tests » (TS engine, stored with checksum) « Soumettre à revue » → submit (gate re-checked) ─► IN_REVIEW reads definition, sources, tests; « Aperçu » « Approuver et publier » + written note publish: tests re-run, four-eyes, sign-offs (policy 2 → first sign-off; second reviewer publishes) PUBLISHED: immutable; audit entries all along Phones: next list / sync → new version, self-tested before use

المؤلف ينشئ الحاسبة والإصدار، يكتب التعريف من المصدر المذكور، يضيف المصدر الأساسي وحالات الاختبار ويشغّلها، ثم يرسل للمراجعة. المراجِع (ليس المؤلف) يقرأ ويعاين ثم يوافق بملاحظة مكتوبة؛ وإن كانت السياسة توقيعين، فالموافقة الأولى توقيع أول والثانية من مراجِع آخر تنشر. بعد النشر لا يتغيّر الإصدار، والهواتف تستلمه في القائمة أو المزامنة التالية.

13.6 ملفات الحمل من جدول بيانات

  1. « Importer un fichier » ← يُقرأ ملف XLSX على الخادم دون تشغيل أي شيء فيه (workbook.ts يقرأ XML داخل الملف المضغوط).
  2. يُعثر على صف الترويسة، تُربط الأعمدة، تُسرد كلمات الحالة؛ ويُفحص كل صف مقابل المكتبة الحالية (المكرّرات، البدائل غير المعروفة).
  3. يربط المشرف الأعمدة وكلمات الحالة، يصحّح الصفوف، ثم « Ajouter à la bibliothèque » ← إصدارات ملفات مسودة، كلها أو لا شيء، ودون تكرار عند النقر المزدوج.
  4. يكمل المؤلفون مستويات الدليل والشروح؛ « Soumettre à relecture »؛ يوافق مشرف آخر؛ وعندها فقط ترى الهواتف الملفات.

13.7 فقدان البريد والهاتف معًا

في الهاتف access_help_screen ← recovery_screen (النموذج، رمز إلى الجهة الجديدة، صورتان إلى الدلو الخاص، « Envoyer la demande ») ← في لوحة الإدارة « Récupération » (المقارنة، « Approuver » مع ملاحظة) ← مهلة 24 ساعة، يُبلَّغ المالك على جهاته القديمة ← المهمة auth.account-recovery: الحجز، استبدال جهات الاتصال، كلمة المرور غير صالحة، إلغاء كل الجلسات ← يدخل الشخص بالجهة الجديدة عبر « Mot de passe oublié ».

13.8 اشتراك يصل إلى نهايته

  1. قبل النهاية بـ14 و3 أيام: إشعارات « Votre abonnement se termine bientôt » (SubscriptionLifecycleService.remind). « Renouveler » مفتوح في آخر 14 يومًا؛ والتجديد يمدّد من النهاية الحالية.
  2. عند النهاية دون تجديد: GRACE لمدة 7 أيام، والوصول باقٍ (advance).
  3. بعد المهلة: EXPIRED. تعطي placeInTier المستوى PROFESSIONAL_UNPAID؛ يحتفظ الطبيب بالعيّنات والمفضلة؛ وتُحذف النسخ دون اتصال للعناصر المقفلة في المزامنة التالية.
  4. أبدًا: لافتات حمراء، أو عدّ تنازلي، أو أزرار استرداد.
