13. Eight journeys through the whole system

Each journey follows one real story from the first tap to the database and back, naming the file at every step. Read one with the three apps open side by side: it is the fastest way to feel how the pieces fit.

13.2 A visitor tries the demo, then creates an account

  1. demo_start_screen → POST /v1/demo/sessions with the installation id → a one-hour demo token + renewal token (SessionVault.saveDemo).
  2. The router moves to Home; GET /v1/me/access answers tier DEMO: only demoSample items open; offline, purchase and profile edit are locked with « Créer un compte » as the unlock path.
  3. Analytics: DEMO_STARTED, then DEMO_FEATURE_VIEWED for each module seen or limit met (no account, no personal data).
  4. « Créer un compte » → sign-up → on confirmation the same installation id marks the demo CONVERTED; the « Démo » funnel in Admin Web counts it.

13.3 Opening a prescription model

Chapter 3.1 followed this request byte by byte. The things to remember: the list shows locked models in place; file-url re-checks access; the PDF comes straight from R2 with a 10-minute URL; its SHA-256 is checked on the phone; ActivityRecorder.referenceViewed adds a history entry; REFERENCE_VIEWED is counted once the PDF has rendered.

13.4 Using a calculator, offline

  1. During the last sync, OfflineSyncController stored the published calculator version (definition + test cases) in drift.
  2. No network: calculatorRuntimeProvider reads the stored version, parses it (definition.dart) and runs its published test cases on the Dart engine (self_test.dart). A failure refuses the calculator.
  3. The doctor types the age, weight, creatinine; each field commits after a pause; evaluate() checks ranges and rules and computes; the band and the formula with the values appear.
  4. Nothing leaves the phone. CALCULATOR_COMPLETED is queued for analytics with the calculator id and version only.

13.5 Authoring and publishing a calculator (two admins)

Author (calculators.draft) Reviewer (calculators.review + publish), NOT the author « Nouveau calculateur » → createCalculator « Nouvelle version » → createVersion (DRAFT) Définition: JSON from the cited source → saveDefinition (checkDefinition) Sources: PRIMARY source (+ validation sources) Tests: cases from the source → « Lancer les tests » (TS engine, stored with checksum) « Soumettre à revue » → submit (gate re-checked) ─► IN_REVIEW reads definition, sources, tests; « Aperçu » « Approuver et publier » + written note publish: tests re-run, four-eyes, sign-offs (policy 2 → first sign-off; second reviewer publishes) PUBLISHED: immutable; audit entries all along Phones: next list / sync → new version, self-tested before use

13.6 Pregnancy profiles from a spreadsheet

  1. « Importer un fichier » → the XLSX is read on the server without running anything in it (workbook.ts reads the XML inside the zip).
  2. The header row is found, columns mapped, status words listed; each row checked against the current library (duplicates, unknown alternatives).
  3. The admin maps columns and status words, corrects rows, then « Ajouter à la bibliothèque » → draft profile versions, all or nothing, idempotent on double click.
  4. Authors complete evidence levels and explanations; « Soumettre à relecture »; a different admin approves; only then do phones see the profiles.

13.7 Lost both e-mail and phone

Mobile access_help_screen → recovery_screen (form, code to the new contact, two photos to the private bucket, « Envoyer la demande ») → Admin Web « Récupération » (compare, « Approuver » with a note) → 24-hour hold, owner notified on the old contacts → auth.account-recovery job: claim, replace contacts, password unusable, all sessions revoked → the person signs in with the new contact through « Mot de passe oublié ».

13.8 A subscription reaches its end

  1. 14 and 3 days before the end: notifications « Votre abonnement se termine bientôt » (SubscriptionLifecycleService.remind). « Renouveler » is open in the last 14 days; a renewal extends from the current end.
  2. At the end without renewal: GRACE for 7 days, access kept (advance).
  3. After grace: EXPIRED. placeInTier gives PROFESSIONAL_UNPAID; the doctor keeps the sample set and favorites; offline copies of locked items are removed at the next sync.
  4. Never: red banners, countdowns, refund buttons.
