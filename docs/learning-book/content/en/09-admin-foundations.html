9. How Admin Web is built — Next.js, React and the console kit

Admin Web is a Next.js application written in React and TypeScript. It has no database and no business rule of its own: every screen reads and writes through the API, and every button it hides is also refused by the API. Its job is to make the team's work fast, clear and safe.

9.2 One origin: the API behind Admin Web

The browser never calls the API's domain. Next.js forwards /admin/v1/* to the API, so the session cookie (__Host-doktool_admin, HTTP-only) belongs to Admin Web's own origin and every write carries Admin Web's Origin header — which the API's boundary guard checks. A strict Content-Security-Policy allows scripts only from the console itself.

9.3 Calling the API

openapi-fetch is typed by schema.d.ts, generated from the API contract: a wrong path, a missing parameter or a misspelled field is a compile error. call() turns any failure into an ApiFailure carrying the API's error code:

[[code apps/admin/src/api/client.ts | export async function call | block]] [[code apps/admin/src/api/client.ts | export function fieldErrors | block]]

Errors are shown with useErrorText() (src/ui/errors.ts), which maps codes to catalogue sentences — never the server's developer message. If a call answers "session ended", the provider reloads the sign-in page and remembers where the admin was.

9.4 Server state with TanStack Query

Every list and detail is a useQuery (or useInfiniteQuery for paged lists) with a query key. Every change is a useMutation; on success it invalidates or updates the keys it affects, so every screen showing that data refreshes. Read the users page's list as the model for all lists:

9.7 Forms

Forms use React Hook Form with a Zod schema holding the same limits as the API (lengths, patterns). The API stays the judge: its VALIDATION_FAILED field errors are put back under the matching fields with fieldErrors().

9.8 Signing in

app/sign-in/sign-in-form.tsx has two steps. The password step answers with a challenge: ENROL the first time (a QR code drawn from the otpauth:// link, to scan with an authenticator app) or VERIFY afterwards. The six-digit code then creates the session cookie. If the 5-minute challenge expires or locks, the form now says why before starting again (audit fix A5).

9.9 Languages and formatting

Messages come from the same catalogue as the app (packages/i18n), under admin.* keys: t('admin.users.title'). A key that does not exist is a compile error (MessageKey type). src/i18n/format.ts formats dates, numbers, money (DZD), file sizes and ages in the chosen language.
