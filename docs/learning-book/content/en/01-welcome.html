1. Welcome — how to read this book

This book walks you through the whole DokTool code base, from the first line the server runs to the last button of the mobile app. Its goal is simple: after reading it, you should be able to open any file and say what it does, why it is there and what happens when someone presses a button — as if you had written it yourself.

1.1 How the book is organised

  • Part 1 — Foundations (chapters 1–3). What DokTool is, how the repository is laid out, and how the three applications talk to each other.
  • Part 2 — The API (chapters 4–8). The NestJS server: how a request is handled, then every module — accounts, access, content, calculators, pregnancy, verification, payments, finance, analytics and the admin side.
  • Part 3 — Admin Web (chapters 9–10). The Next.js console the team uses: its building blocks, then every screen and button.
  • Part 4 — The mobile app (chapters 11–12). The Flutter app: its foundations, then every screen and button.
  • Part 5 — Journeys (chapter 13). Eight complete stories followed through all three applications, step by step.
  • Part 6 — Working on the code (chapter 14). Tests, CI, and recipes for the changes you will make most often.
  • Appendix A. Generated from the code: every file, every documented function and every commented button, in the order of the file. It is the reference you keep open next to the editor.
How to study. Read a chapter, then open the files it names in your editor and read them top to bottom. Every function and every button now has a short comment explaining it (that was part of the October 2026 audit). Code shown in this book is not retyped: it is pulled from the files when the book is built, with its real line numbers, so what you read here is exactly what is in the repository.

1.2 What DokTool is

DokTool is a mobile clinical utility for doctors, residents and medical students in Algeria. It is deliberately small and fast. It is not a patient record, a prescription generator, a drug database, a chatbot or a marketing platform. It offers four things:

ResourceWhat the doctor does with it
Ordonnances (prescription models)Searches, finds a reference model and reads it as a PDF. Read-only: no editing, no patient field, no printing, no sharing.
Certificats (certificate models)The same, for medical certificates.
Calculateurs (clinical calculators)Picks a score or formula, enters validated values, gets a result with its interpretation band and its published source.
Grossesse · Allaitement (pregnancy and lactation)Looks up a substance and reads, per trimester and for breastfeeding, the conduct and the evidence level — always separate, never a "safe / unsafe" verdict.

The product summary in CLAUDE.md fits in three lines, and the whole code base serves them:

References SEARCH → FIND REFERENCE MODEL → VIEW PDF → USE AS CLINICAL REFERENCE Calculators SELECT TOOL → ENTER VALIDATED INPUTS → CALCULATE → REVIEW RESULT + SOURCE → DONE Prospects DEMO → EXPLORE → UNDERSTAND → SUBSCRIBE

1.4 The rules every line of code respects

These rules come from the Product Owner's decisions (docs/adr/ADR-006-product-owner-decisions.md) and the design system. Whenever you wonder "why is this code so careful here?", the answer is usually one of them.

1. The backend decides access. The server computes an AccessProfile (tier + the state of every feature) and re-checks it on every endpoint. The app only draws what it receives; it never says if (student).
2. Locked is not hidden. A locked item stays visible with its lock and the reason. Only deferred modules (drug database, prescription generation…) are never shown at all.
3. No patient data, anywhere. Calculator inputs never leave the phone; analytics carry no free text, no search words and no input values.
4. Reference PDFs are read-only. No editor, no export, no print, no share, no download button. Files live in private storage and are reached only through short-lived signed URLs.
5. Clinical content is never invented. A calculator formula comes from a cited source, is reviewed by someone other than its author, has test cases, and is immutable once published. AI never writes or changes a formula or a profile.
6. Calm money. Subscriptions show what is included, the price, the duration and « non remboursable », with no red, no countdown and no refund workflow.
7. Bilingual from one catalogue. French and English for every text, from packages/i18n. No Arabic or right-to-left inside the app itself.
