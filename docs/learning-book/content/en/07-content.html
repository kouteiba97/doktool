7. Content: reference PDFs, calculators, pregnancy, search, offline

The four resources of DokTool live in four modules — reference-library, calculators, pregnancy and (for finding them) search — helped by storage, clinical-review, activity and offline. Each has an app side (read-only, access-checked) and an admin side (authoring, review, publication, audited).

7.1 Reference library: ordonnances and certificates

A reference model is a PDF uploaded by the Super Admin, with minimal metadata: a French title (pre-filled from the file name), an optional English title, the demoSample flag and a status. The PDF is the content; nobody edits it in DokTool.

7.3 Calculators: a formula as data

A calculator is never code. It is a definition — JSON validated by a Zod schema — that both engines (TypeScript on the server, Dart on the phone) interpret the same way. A definition holds:

  • inputs: NUMBER/INTEGER (with units from a sourced registry and three ranges: hard — impossible values; validated — where the formula was validated; plausible — beyond it, a « vérifiez la valeur » note), CHOICE (answers, optionally with points) and BOOLEAN;
  • cross-field rules (e.g. diastolic must be below systolic);
  • the formula, a tree over a closed set of operators;
  • the result (unit, decimals), the interpretation bands and the limitations.
[[code apps/api/src/modules/calculators/engine/definition.ts | export type Expr | 10]] [[code apps/api/src/modules/calculators/engine/definition.ts | export const BINARY_OPS | 16]]

There is no eval, no free-form expression and no operator outside these lists: a definition cannot do anything the engine does not know. checkDefinition then checks what a schema cannot: unique keys, known units, nested ranges, a well-typed formula, ordered bands that do not overlap.

The engine

[[code apps/api/src/modules/calculators/engine/evaluate.ts | export function evaluate( | block]]

Read the order: presence and types → hard ranges → cross-field rules → validated ranges → plausibility notes → formula → band. The engine never returns a result for invalid input or input outside the validated range: it returns the issues instead, and the app explains them. Rounding is "half away from zero" computed on the decimal text, so 2.675 rounds the same way in TypeScript and Dart.

Two engines, one truth. The TypeScript engine is authoritative: admins' test runs and publication use it. The Dart engine lets the phone compute offline; before using a version, the app runs the version's published test cases on its own engine (« self-test ») and refuses the calculator if one fails. packages/calculator-vectors holds shared cases both engines must pass in CI.

7.4 Grossesse · Allaitement

A substance (names, ATC code, synonyms, demoSample, enabled) has profile versions, governed like calculators (draft → review → published, author ≠ reviewer, optional second sign-off). A profile's content has two blocks: pregnancy (T1, T2, T3, peripartum) and lactation. For each period: a conduct (CONTRAINDICATED, AVOID, OCCASIONAL_USE or none) and, separately, an evidence level from 0 (« Absence de données ») to 4 (« Données robustes ») with its sources — never merged into a "safe" verdict.

Three more tools exist on the admin side:

  • Spreadsheet import (ADR-025): an uploaded XLSX becomes a preview batch; the admin maps columns and status words, corrects rows, then commits — which writes drafts, never published content.
  • Merging duplicates (ADR-027): a duplicate substance's names become synonyms of the one kept; favorites and links of the duplicate open the kept substance; the merge can be undone.
  • User reports (« Signaler une erreur » in the app) arrive in a queue the clinical team resolves.

7.5 Search

Global search (GET /v1/search?q=…) runs over enabled reference models, published calculators and listed substances, with the viewer's access on each hit (locked results stay in place). Ranking is in ranking.ts: text is normalised (lower case, no accents), each query word may have typos (none up to 2 letters, 1 up to 5, 2 above, Damerau-Levenshtein), exact and prefix matches score higher, and a query naming a category (« certificat… ») puts that group first. Nothing is ever boosted commercially.
