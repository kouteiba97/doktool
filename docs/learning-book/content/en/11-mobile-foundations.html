11. How the mobile app is built — Flutter, Riverpod, go_router, drift

The app is written in Dart with Flutter, one code base for iOS and Android. Four libraries shape every file: Riverpod (state and dependencies), go_router (screens and redirects), dio with a generated client (the API), and drift (a small SQLite database on the phone). This chapter explains each with the app's own code.

11.4 The session

SessionVault keeps the secrets: refresh and renewal tokens in the Keychain / Keystore (SecureStore), the access token in memory only. When several requests need a new access token at once, they all wait for the same refresh ("single-flight") — refresh tokens are single-use, so two parallel refreshes would revoke the session:

11.5 Routes and redirects

Every screen has a path in Routes. The redirect function decides, on every navigation and whenever the session or the account changes, where the person is allowed to be:

[[code apps/mobile/lib/src/router/app_router.dart | String? redirectFor({ | block]]
  • Signed out → only public pages (welcome, sign-in, sign-up, codes, demo start, recovery).
  • Demo → never public pages again, never account-only pages (subscription, profile edit, verification…).
  • Account without a profession → « Qui êtes-vous ? » first.
  • Locked content is never hidden by a redirect: the screen renders its locked state.

The three tabs (Accueil, Bibliothèque, Profil) are a StatefulShellRoute: each tab keeps its own stack, and tapping the active tab again goes back to its first screen. The round button in the middle of the bar opens search over everything; « Activité et favoris » is reached from Profil.

11.6 Talking to the API

The client under core/api/generated/ is produced from openapi.json by swagger_parser + build_runner: one method per endpoint (api.calculators.calculatorsControllerList()) and one immutable class per DTO. Two interceptors are added to dio: the language (Accept-Language) and the token (AuthInterceptor). Failures become an ApiError with the server's code; screens translate their specific codes and fall back to commonErrorText.

11.8 The widget kit and tokens

Screens are built from lib/src/ui/: DtButton (one primary per region, a spinner while loading, disabled when onPressed is null), DtTextField (label above, error on blur), DtAlert, DtBadge (always a word), ContentRow (a list row with its lock), DtPickerField (searchable bottom-sheet picker), DtSegmentedControl, DtPillTabs, DtChoiceList (long answers in full), the glass hero (DtGlass, DtHeroAppBar) and LockLabel / showLockSheet. Colours, spacing, radii and durations come only from tokens: context.colors.brand, DtSpace.s4, DtRadius.lg. CI rejects a raw colour literal.

11.9 Texts

Every text is AppLocalizations.of(context).someKey, generated from the ARB files that packages/i18n builds. To add a text: add the key in French and English to the catalogue, rebuild the ARB, run flutter gen-l10n (chapter 14).

11.10 Tests

apps/mobile/test/ has unit tests (engine, vectors, offline store, core) and widget tests that pump real screens with fake providers. accessibility_test.dart checks every main screen in light and dark, at 200 % text, for touch size (44 px), labels and contrast.
