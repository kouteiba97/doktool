2. The repository — where everything lives

DokTool is one Git repository (a monorepo) holding three applications and four shared packages. The web console and the mobile app are already completely separate: they live in different folders, use different languages and frameworks, and never import each other's code. What they share is a contract with the server, generated automatically.

2.1 The top-level folders

2.2 How the web app and the mobile app are separated

The question "where is the web code, where is the mobile code?" has a clean answer:

Admin WebMobile app
Folderapps/adminapps/mobile
LanguageTypeScript + React (TSX)Dart
FrameworkNext.js (App Router)Flutter
Who uses itThe DokTool team, on a computer (≥ 1024 px)Doctors, residents, students, demo visitors, on a phone
API it calls/admin/v1/* with a session cookie + 2FA/v1/* with a bearer token
Generated clientapps/admin/src/api/schema.d.tsapps/mobile/lib/src/core/api/generated/
Package managernpm (workspace)flutter pub
TestsVitest (apps/admin/src/test)flutter test (apps/mobile/test)

The only things they have in common come from packages/: the same words (i18n), the same colours (design tokens) and the same API contract. None of these is imported as source code; each is generated into the format the app needs.

design/system/tokens.json ──generate──► tokens.css + tailwind preset (admin) + doktool_tokens.dart (mobile) packages/i18n/messages.*.json ─build──► admin catalogue (TS) + lib/l10n/*.arb (mobile) apps/api (decorators) ──openapi──► packages/api-contract/openapi.json ──► schema.d.ts (admin) + Dart client (mobile)
Never edit a generated file by hand. schema.d.ts, everything under core/api/generated/, doktool_tokens.dart and the ARB files are rewritten by their generators. CI compares them with a fresh generation and fails on any difference ("drift").

2.3 How the three applications talk

┌────────────────────┐ HTTPS /v1/* (Bearer access token) ┌──────────────────────────┐ │ Mobile (Flutter) │ ─────────────────────────────────────────────► │ │──► PostgreSQL (Prisma) └────────────────────┘ │ API (NestJS) │──► Cloudflare R2 (files) ┌────────────────────┐ HTTPS /admin/v1/* (cookie + TOTP 2FA) │ apps/api — the judge │──► SMS / e-mail providers │ Admin Web (Next.js)│ ─────────────────────────────────────────────► │ of every rule │──► Chargily / SATIM payments └────────────────────┘ └──────────────────────────┘ PDFs and photos go straight between the apps and R2 with short-lived signed URLs the API hands out.

2.4 Inside apps/api

  • src/main.ts — starts the server. src/app.setup.ts — HTTP settings shared with the tests. src/app.module.ts — assembles everything.
  • src/config/ — reads and validates the environment variables (env.ts).
  • src/common/ — small shared helpers: the error envelope, client info, CSV and search text.
  • src/infrastructure/ — technical services every module may use: the database client, cryptography, background jobs, rate limits, e-mail and SMS, token verification.
  • src/modules/ — the 20 domain modules, one per business area. Each owns its tables and exposes only what its index.ts exports.
  • src/scripts/ — command-line tools: create an admin, generate the OpenAPI contract, seed demo data, Medicalcul extraction and import.
  • prisma/schema.prisma — every table, grouped by owning module.

2.6 Running everything on your machine

From the repository root, once:

npm install # installs API, Admin Web and packages cp apps/api/.env.example apps/api/.env # then fill DATABASE_URL and fresh 32+ char secrets cp apps/admin/.env.example apps/admin/.env npm run prisma:migrate:deploy -w @doktool/api # creates the tables npm run admin:create -w @doktool/api -- --email you@example.dz --name "Your Name"

Then, in three terminals:

npm run start:dev -w @doktool/api # API on http://localhost:3000 (Swagger at /docs) npm run dev -w @doktool/admin # Admin Web on http://localhost:3001 cd apps/mobile flutter pub get dart run build_runner build --delete-conflicting-outputs flutter gen-l10n flutter run --dart-define=API_BASE_URL=http://localhost:3000
Sample data. npm run demo:seed -w @doktool/api fills a database whose name ends in _demo with demonstration accounts and content (it refuses any other database). The passwords it prints are shown once.

2.7 The one command that checks everything

DATABASE_URL=postgresql://…/doktool_test npm run ci cd apps/mobile && flutter analyze && flutter test

npm run ci runs, in order: Prettier formatting, ESLint, TypeScript type checks, the i18n parity check (every key in both languages), the design-token checks (no raw colour, radius, blur or duration in the code), the OpenAPI drift check, the admin client drift check, then every test of every workspace. At the end of the October 2026 audit it was green: 613 API tests, 30 Admin Web tests, the package tests, and 167 Flutter tests.
